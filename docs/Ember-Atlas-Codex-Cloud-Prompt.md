## Mission

Address the NASA Space Apps 2026 challenge **Harmonization of MODIS and VIIRS Hot Spots**. Fire managers, land managers, researchers, and responders need to examine when satellite-detected burning activity was unusual in a chosen area. The historical record spans sensors with different pixel footprints, detection sensitivity, overpass times, and cloud and sampling conditions. A direct splice of hotspot counts can change the apparent trend when the instrument changes.

Build a public, working application that puts real NASA FIRMS observations on a common spatial and temporal basis, validates cross-sensor comparability, and turns the result into an interactive burning-activity calendar with regional and date selection, historical comparisons, and downloadable evidence. Start with the Pantanal, Brazil. The principal judge question is **“Was this a noteworthy fire season, or did the new sensor simply report more detections?”**

## Harmonization and scientific acceptance

Harmonization means creating a documented, comparable **satellite-observed activity measure** across instruments over the same area and time. It includes common support, a measured sensor transfer on overlapping data, and validation on unseen years. Keep native detections inspectable. The result remains sensitive to clouds, timing and detection limits. A hotspot record is a thermal anomaly detection. Avoid claiming unique fires, burned area, ground truth, or forecasts from hotspot counts.

1. **Common support.** Align both products on a fixed globally anchored grid per UTC day inside the chosen AOI. Start with the existing 0.05-degree baseline and disclose latitude dependence, or use a documented equal-area grid with a reproducible origin and resolution. Count each occupied cell once per product per day, then sum cell-days by month. Keep raw detections, product provenance and completeness in companion series. Quantify sensitivity to reasonable alternate cell sizes and confidence rules, plus day/night or platform mix when data allow. If metrics change materially with a setting, report it.
2. **Matched overlap.** Match by AOI and complete paired month. Freeze the split by year, training period, grid and confidence settings before examining holdout results. Retain only matched months for evaluation and record dropped periods and reasons. Treat low-count denominators explicitly. Do not tune on August or September 2024 if those months are presented as holdout evidence.
3. **Transfer.** Use MODIS occupied cell-days as the reference unit. Start with a transparent seasonal VIIRS-to-MODIS multiplicative factor computed on training months, pooling matched counts with a documented minimum support rule and pooled fallback for sparse seasons. Apply it only inside the domain with adequate evidence. Use separate native series for unvalidated regions. Do not apply Pantanal calibration to an arbitrary polygon or nation-wide query. Display legacy MODIS followed by calibrated VIIRS with a documented transition date, keeping both separately visible in overlap. Never sum their estimates into one harmonized observation.
4. **Validation.** Compare matched-year MODIS versus VIIRS raw-count differences as a native-unit diagnostic. Separately compare unscaled and calibrated VIIRS against observed MODIS **on the same occupied cell-day scale**, using identical holdout periods. Publish chronological split, matched sample sizes, monthly MAE, signed bias, seasonal results and change around the handoff where assessable. Show sample size and uncertainty. Use year-block resampling only with adequate independent years, and avoid false precision otherwise. MODIS is the reference for comparability, not an independent truth label. If the transfer fails the predeclared improvement criterion or matched years are insufficient, expose the real sensor-specific and grid-normalized series and mark calibration unavailable where relevant. State this plainly in delivery notes. Never cherry-pick the best holdout result.
5. **Anomalies.** Use complete comparable prior years for the same calendar month, exclude the target year, show baseline years and sample size, and compute absolute difference from the historical median. Show percent only with a nonzero baseline. Mark small baselines or incomplete months clearly. Structure outputs so another engineer can reproduce the same values from versioned inputs.
